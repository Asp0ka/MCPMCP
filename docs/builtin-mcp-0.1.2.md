# 内置 MCP HTTP 与服务器设置

## 用法

MCP 服务器已放进客户端模组 JAR；直接 Streamable HTTP 连接不需要外部 Python 进程。旧 stdio 桥接保留用于兼容。

新配置默认 `port=5210`、`portEnd=5220`、`serverEnabled=true`。开游戏时按端口从小到大尝试，仅端口绑定占用时换下一个；到结束端口仍无可用监听则保持停止，设置页显示失败原因，不无限重试。只监听 127.0.0.1。

Forge 模组列表 → MCP Minecraft Plus → 配置 → MCP 服务器：

- 起始/结束端口和“随游戏自动启动”是草稿，点击“保存启动设置”后写入 `config/mcpmcp.json`。端口范围支持1024–65535、包含首尾最多11个；起始不得大于结束。
- 保存设置不改变当前服务器运行状态；端口在下次启动服务器时应用，自动启动偏好在下次开游戏时应用。
- “启动/停止服务器（仅本次）”只控制当前进程，不写config，也不改自动启动偏好；停服后每秒配置重载不会把它重新拉起。
- 手动停止立即撤销旧会话请求，清理本服务发起的任务/输入，HTTP收尾放后台；收尾期间重开返回 `server_stopping`，完成后可重试。
- 旧配置缺新增字段时，原起始端口保留，结束端口推导为起始+10（上限65535），自动启动默认开启。加载迁移不会改写原文件；保存时保留token、权限和未知字段。

## 连接

实际地址见设置页，或同实例 `config/mcpmcp-runtime.json` 的 `endpoint`。发现文件仅记录本次运行状态与实例信息，不含token；停服/退出时标为 `running=false, port=0`。AI客户端应在本地安全读取token，并使用 `Authorization: Bearer <token>` 请求头认证；token仅保留在本地。

MCP endpoint 是 `http://127.0.0.1:<实际端口>/mcp`。本实现支持无状态 Streamable HTTP 的JSON响应，工具能力与旧桥接一致共19项；initialize、ping、tools/list、tools/call及初始化通知均在Java实现。GET返回405（不提供SSE），不声明session、listChanged或其它可选能力。当前兼容2025-03-26、2025-06-18、2025-11-25；不提供2024旧HTTP+SSE传输。原 `/call` 仅作兼容接口，不是标准MCP endpoint。

既有 `bridge/mcp_server.py --config <实例>/config/mcpmcp.json` 仍可用于stdio客户端，会自动读取发现文件而非误用起始端口；发现记录停服或实例不匹配时拒绝调用。直接HTTP无需Python。

官方协议核对依据：MCP specification 2025-11-25 的 basic/transports、server/tools。JSON响应及GET405是当前传输的合法profile；不是用 `/call` 冒充MCP。

## 独立审查后补充

兼容桥接现在先用不带Bearer的随机挑战验证服务身份：HMAC-SHA256签名绑定发现记录中的PID、instance、port与本次nonce，验证成功后仅在同一连接上传凭据，不接受重定向或自动重连。陈旧发现文件/端口复用探针未收到凭据或游戏请求。新模组会发布发现文件，旧版本没有发现文件时保留原旧接口兼容。

设置页缩放后保留未保存草稿，最终JAR游戏内重现操作验证自动启动草稿仍为关且config字节不变。审查与RED/GREEN证据见 evidence/builtin-mcp-0.1.2/review.md。
